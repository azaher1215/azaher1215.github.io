A modular nav stack for Spot & Jackal, made to swap

Reproducible ROS 2 navigation pipelines — four per robot — running side-by-side on Humble and Jazzy. Pick a sensor, swap a SLAM method, change a planner, run the same mission. Every configuration ships with its node graph, parameters, and a Webots or Gazebo simulation.

Overview

One mission. Many stacks. Identical interface.

This project decomposes a typical ground-robot navigation pipeline into interchangeable layers — sensing, SLAM, localization, and Nav2 planning — and provides a launch-file scaffold that lets you mix and match them. The goal is to make it trivial to test different stacks without rebuilding a workspace from scratch.

  1. 01 Common URDFs and TF trees per robot Jackal on Jazzy and Spot on Humble share a normalised frame layout so any stack drops in.
  2. 02 Pluggable SLAM SLAM Toolbox, FAST-LIO, ORB-SLAM3, and RTAB-Map — each behind a single launch file.
  3. 03 Nav2 in every stack Configured planner / controller / behaviour tree variants live as named YAML profiles.
  4. 04 Identical evaluation harness Same waypoints, same metrics, same recordings — comparable across both robots.

Get it running

Install, build, and launch.

Both workspaces are built with colcon against the matching ROS 2 distro. Each branch ships its own dependency layout. Pick the branch that matches your robot. For the full instructions, see the corresponding README (private repo) file for each robot on GitHub.
